# Acceptance Authority — ProofLoop 新流程模型

> 本文件是 ProofLoop 新流程模型的 tracked 验收权威，替代被 `.gitignore` 忽略的 `.docs/`
> 设计细节。它定义依赖有序的主流程 E2E、异常路径 E2E 与 Static Architecture Acceptance；
> 不以表格勾选、Agent 摘要或 ignored 文档替代可复核证据。
>
> 依据：`PRD.md`、`tech-spec/architecture.md`、`tech-spec/contracts.md`。
> `CONTEXT.md` 仅作 Working Memory 参考，不是 Authority，也不参与验收结论。

## 1. 验收原则

1. 从 `PROPOSE_READY` 到 `PROJECT_READY` 的任何合法主流程路径，以及 repair / replan /
   recovery 路径，均不依赖 Admission、Receipt Chain、Manifest credential、Context Gate、
   `stage next` / Primary Next Action、Stage Gate / finalize-close credential、legacy
   currentness-recovery。
2. 每个 E2E 都有 PASS 或 typed BLOCKED；环境失败不重写为 PASS。
3. 证据必须能从 durable refs/digests 与命令 transcript 重读；模型摘要、`sent`、`idle`、
   `done`、checkbox 或 session 状态不构成证据。
4. 历史/迁移说明段显式标记 `Historical/legacy`，不形成 route。
5. MES integrity incident 时，physical quarantine 与 Brain higher-priority blocker 优先于任何 stale/public Execute projection；`MES_MAINTENANCE` implementation、evidence-only review、controlled recovery 与受影响 Stage/cycle 的 resume 必须按 E2E-24/25/26 和 current Authority 执行。

## 7. Testing Guidance

- 纯 decision logic（replan-impact 分类、三层绑定、status 投影）：使用 Node 25 内置
  `node:test`。
- Host/Subagent host/transport：使用真实 workspace/adapter；无法真实运行时记录 `BLOCKED`，
  不使用 mock 伪造 `PASS`。
- Git boundary：只在临时 Git fixture 中测试；生产工作树不执行直接 `git add`/`git commit`。
- MES/status/transaction：按 mes.md Contract fixtures（正常/异常/restart），MES 输出不含 next action；transaction fixtures 必须覆盖 preserve-by-default、caller no full snapshot、canonical binding resolution/typo atomic no-write、invalid-history isolation、Sep 10/12/13 regressions、raw writer negative path；`MES_MAINTENANCE` fixtures 还必须覆盖 packet/result/ACK mode closure、frozen/forensic/audit exact binding、no normal identity/fact write、Git evidence recovery、maintenance Review evidence-only 与 post-recovery lane invalidation；所有 mutation test 使用 `mkdtemp` isolated root，真实 `.proofloop/mes` 在 remediation 期间保持 directory quarantine 与 SHA/count 不变；terminal currentness fixture 必须覆盖 open-cycle precedence、chain-tip selection、legacy/history、branch/cycle/duplicate/missing-target fail-closed 与 human/JSON/detail `project_terminal` 输出。
- Planning generation/continuation fixtures 必须覆盖：同 cycle append-only 多 generation（唯一 tip）、ref/digest 不变的 fresh re-acceptance、branch/环/悬空/跨 stage/跨 cycle/half-new/closed-cycle no-write、绑定旧 generation 的 downstream non-authorizing、`resume` / `replan` / `restart` 三态区分、`EXISTING_SEAM` 缺 seam 的 `PLAN_GAP` / `RESULT_INVALID`。
- 每个失败场景都检查 dirty/index/受保护路径未被错误写入；保留原始诊断和恢复方向。
- E2E 证据必须能从 durable refs/digests 和命令 transcript 重读；模型摘要、`sent`、
  `idle`、`done` 或 checkbox 不构成证据。
- 不运行会修改 Runtime dist 的命令（`npm run build` 由构建任务单独执行）。
